# HM Maths LMS — Hasitha Madusanka · A/L Combined Mathematics

Production-ready tuition LMS (pb.lk-style design, English + සිංහල) on a **100 % free stack**: Next.js 15 (App Router, Server Actions, TypeScript) · Tailwind + shadcn-style UI · Framer Motion · Supabase (Postgres, Auth, RLS, Storage, Realtime) · YouTube unlisted video · Vercel Hobby.

## 1. One-time Supabase setup (≈ 2 minutes)

1. Supabase Dashboard → **SQL Editor → New query** → paste `supabase/migrations/0001_init.sql` → **Run**.
   It creates all tables, triggers, RLS policies, RPCs, the 4 storage buckets and enables Realtime for notices. It is safe to re-run.
2. The admin login (`admin@nativelaunch.xyz`) is already created in Auth; the script promotes it to `admin` automatically.
   To create/reset an admin later: `npm run create-admin -- you@example.com "NewPassword"`.
3. Verify everything live: `npm run verify` (creates temporary users/classes, tests every security rule, then deletes them).

## 2. Run locally

```bash
npm install
cp .env.example .env.local   # already filled in this bundle
npm run dev                  # http://localhost:3000
```

## 3. Deploy to Vercel (free)

1. Push this folder to a GitHub repo → **vercel.com → New Project → Import**.
2. Add Environment Variables: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` (server-only), `NEXT_PUBLIC_SITE_URL` (your Vercel URL), optional `CAPTCHA_SECRET`.
3. Deploy. In Supabase → Authentication → URL Configuration set **Site URL** to the Vercel URL.

## 4. Things to customise (no coding needed)

**All text on the site lives in JSON** — edit, save, redeploy:

| What | Where |
| --- | --- |
| Every label, heading, button, error message (English) | `src/i18n/messages/en/*.json` |
| Same in Sinhala | `src/i18n/messages/si/*.json` (missing keys fall back to English) |
| Home page: hero text, announcements ticker, story milestones, testimonials, FAQ, placeholder classes | `src/i18n/messages/<lang>/landing.json` |
| Dashboard banner slides | `portal.json` → `dashboard.banners` |
| Phone, WhatsApp, e-mail, address, social links, **bank accounts (placeholders now)**, WhatsApp channels, testimonial YouTube video ID | `src/content/site.json` |
| Tutor photo on the hero / photo on login & register | drop `public/images/tutor.png` (transparent PNG) and `public/images/auth-bg.jpg` — shown automatically when present |
| Brand colours | `tailwind.config.ts` (`brand` = orange, `teal`) and `src/app/globals.css` |
| Pre-join window (20 min) / live length | `src/lib/constants.ts` → `LIVE_UNLOCK_MINUTES`, `LIVE_DURATION_MINUTES` |

Files: `common.json` (shared words, statuses, months), `landing.json` (home page), `auth.json` (login/register), `portal.json` (student area), `admin.json` (admin panel), `errors.json` (all validation/server messages). Keep `{placeholders}` like `{name}` unchanged. Run `npm run test:i18n` after editing — it checks both languages have the same keys/placeholders and that every key used in code exists.

Visitors switch language with the **සිංහල / English** button (remembered in a cookie; first visit follows the browser language).

## 5. How it works

- **Students** register (first/last name, mobile, NIC, A/L year, center, school, district, password strength meter, maths captcha) with mobile + NIC + A/L year + center + school/district. They log in with their **mobile number** (mapped to an internal e-mail, so no paid SMS provider is needed). A Student ID `HM-MATHS-<YEAR>-<4 digits>` is generated by a database trigger.
- **Free Zone** – classes marked *Free* are open to every registered student.
- **Paid classes** – student picks a month (current, next, or past “archive pack”), sees the bank details, uploads a slip → `pending`. Admin approves in **Slip approvals** → that exact month unlocks (recordings, tutes, live link). Cash payments: “Grant access manually”.
- **Classroom** – Live Class Hub with a countdown; the live link is not even sent to the browser until **20 minutes before start**. Recordings by week with a moving **phone + NIC watermark** (stays on top in fullscreen). Tute PDFs via short-lived signed links checked by storage RLS.
- **Exams** – MCQ timing and marking happen **inside Postgres** (`start_exam` / `submit_mcq`), so answers and the key never reach the browser before submission; auto-submit at zero; review mode; batch leaderboard. Structured papers: download PDF, upload answer-sheet photos, admin grades.
- **Notices** – General / Urgent / Exam Notice, optionally targeted to a class and/or batch; delivered in real time.
- **Security** – every table has RLS. Students cannot change role/Student ID/mobile/NIC, approve their own slips, read other students’ data, or tamper with scores. The service-role key is only used server-side for registration and admin password resets.

## 6. Tests

- `npm run test:sql` – runs the full migration in an in-memory Postgres (PGlite) and checks 30+ RLS/workflow rules offline.
- `npm run verify` – the same journey against your real Supabase project (33 live checks).
- `npm run test:i18n` – translation key/placeholder parity + every `t("…")` key used in code exists.
- `npm run test:ui` – (first time: `npx playwright install chromium`) full browser journey (Playwright) against a running app: register with captcha → login → unpaid portal → enroll + slip upload → admin approves in UI → class unlocks → live countdown → MCQ attempt + server marking → review → leaderboard → profile → Sinhala + mobile screenshots. Usage: `npm run build && npm start` in one terminal, then `ADMIN_PW="…" BASE=http://localhost:3000 npm run test:ui`. All test data is deleted afterwards.
